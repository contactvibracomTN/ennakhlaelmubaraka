0. Comment lire ce guide

Ce guide est fait pour quelqu’un qui entend parler de « MCP » pour la première fois. Il ne suppose aucune connaissance en programmation. Quand un mot technique apparaît, il est expliqué juste après, et il se retrouve dans le glossaire visuel.

Si vous êtes pressé

Lisez la partie 1, puis suivez les 6 étapes. Revenez aux autres parties seulement si un point vous bloque.

Si vous préparez une équipe

Partagez les checklists et la règle « lecture avant écriture ». Ce sont elles qui évitent la majorité des erreurs.

Si vous aimez les images

Les schémas et maquettes sont intégrés au document. Ils sont volontairement anonymes : aucun compte réel, aucun identifiant et aucun secret n’apparaissent.

La promesse de ce guide

À la fin, vous saurez dire : quel outil je connecte, pourquoi je le connecte, quelles autorisations je donne, et comment refuser une action qui dépasse ce que je voulais faire.

Les noms d’outils et les libellés des interfaces Meta peuvent évoluer. Si un écran diffère légèrement de la maquette, cherchez la fonction — pas le mot exact.

1. Comprendre un MCP en 5 minutes

Une phrase simple

Un MCP est un intermédiaire : il permet à l’endroit où vous écrivez vos demandes de parler proprement à un service externe, ici Meta.

Ce qu’un MCP fait

  • Il présente une liste d’outils compréhensibles : « lister les pages », « lire les statistiques », « chercher des commentaires ».
  • Il traduit votre demande en appel technique vers Meta.
  • Il ramène une réponse que votre client peut vous afficher.

Ce qu’un MCP ne fait pas

  • Il ne décide pas à votre place de publier, répondre ou modifier un budget.
  • Il ne contourne pas les autorisations : si Meta refuse, il refuse aussi.
  • Il ne rend pas un serveur « connecté » automatiquement utilisable : il faut tester une lecture simple.

Les trois couches à ne pas confondre

L’application Meta

C’est l’identité technique que vous créez chez Meta. Elle porte les autorisations.

La Page ou le compte pro

Ce sont vos données réelles : publications, commentaires, statistiques, campagnes.

Le client MCP

C’est l’endroit où vous discutez. Il utilise le serveur MCP, mais il ne remplace pas Meta.

Image mentale

L’application Meta est le badge d’accès, la Page est le bâtiment, et le MCP est le guide qui sait frapper à la bonne porte. Le guide n’ouvre rien sans badge valide.

N’ajoutez que le serveur dont vous avez besoin aujourd’hui. Chaque outil supplémentaire ajoute des possibilités… et donc des façons de se tromper.

3. Parcours d’installation en 6 étapes

Suivez cet ordre. Il évite de devoir refaire une authentification parce qu’une autorisation manquait.

1Choisir le serveur
2Vérifier le client
3Préparer l’application
4Donner le minimum de droits
5Connecter
6Tester une lecture

Choisir le serveur

Partez de votre besoin : statistiques ? campagnes ? messagerie ? Reportez-vous au tableau précédent.

Vérifier le client MCP

Regardez la documentation du serveur : tel client est parfois pris en charge pour un outil, mais pas pour un autre. Ne supposez pas que tout est compatible partout.

Préparer l’application Meta

Utilisez une application dédiée, avec un nom clair. Ajoutez le site web de l’organisation si le formulaire le demande. Gardez l’application en brouillon / non publiée tant que tout n’est pas vérifié.

Donner le minimum de droits

Cochez seulement les autorisations nécessaires à la tâche. Commencez par la lecture. Laissez l’écriture de côté jusqu’à ce que vous en ayez réellement besoin.

Connecter

Deux cas fréquents sont expliqués juste après : OAuth (connexion dans le navigateur) et token System User (identité de service, pour un flux automatisé).

Tester une lecture

Demandez une information sans danger, par exemple : « Liste mes pages » ou « Donne les 3 dernières publications ». Un serveur affiché comme connecté n’est fiable qu’après cet essai.

Visuel : écran de consentement simplifié

Deux façons de se connecter

OAuth

Le client ouvre une page Meta. Vous vous connectez, vous lisez les autorisations, vous acceptez. C’est le plus simple pour une personne.

Utile pour : navigation, exploration, tests ponctuels.

Token System User

C’est une identité « robot » créée dans le gestionnaire d’entreprise, avec un rôle précis et une durée de vie limitée. On l’utilise pour un flux répétitif, jamais dans une conversation.

Utile pour : un serveur local, une tâche planifiée, un usage serveur à serveur.

Ne jamais faire

Ne collez pas un token, un secret d’application ou un mot de passe dans un chat, un document partagé ou une capture d’écran. Un secret vu une fois doit être considéré comme compromis.

Où mettre un token quand c’est vraiment nécessaire ?

Dans un emplacement privé prévu à cet effet, par exemple un fichier d’environnement local non partagé. Le guide ne montre aucune valeur réelle : utilisez toujours un espace réservé comme <VOTRE_TOKEN>.

META_ACCESS_TOKEN=<VOTRE_TOKEN>
META_PAGE_ID=<ID_DE_LA_PAGE>

Si le fichier est versionné, vérifiez qu’il est bien ignoré par le système de suivi avant d’écrire quoi que ce soit.

Et les URL de rappel locales ?

Certains outils affichent une adresse du type http://localhost:<PORT>/callback. Elle sert à l’ordinateur qui lance l’outil. En général, vous n’avez pas à l’enregistrer telle quelle dans Meta : suivez la procédure indiquée par le serveur MCP. Si un port est déjà utilisé, choisissez-en un autre libre et gardez la même valeur dans la configuration.

À éviter au début

Ces autorisations permettent d’agir. Elles peuvent être légitimes plus tard, mais n’ont rien à faire dans une première configuration.

  • ads_management — modifier des campagnes ou des budgets.
  • pages_manage_posts — publier sur une Page.
  • instagram_content_publish — publier sur Instagram.
  • instagram_manage_comments — répondre à des commentaires.
  • Toute autorisation de messagerie si vous ne traitez pas réellement des conversations.
Niveau Standard / Advanced

Certaines lectures sont disponibles en accès Standard, d’autres demandent un accès avancé. Si une erreur dit qu’une permission ou une fonctionnalité manque, ce n’est pas forcément un bug de votre MCP : c’est souvent l’application qui n’a pas encore été approuvée pour cet usage.

À quoi sert la revue d’application ?

Quand vous demandez un accès avancé, Meta peut demander une description de votre usage, une courte vidéo de démonstration et un appel de test réussi. Le compteur d’appel peut mettre jusqu’à 24 heures à se mettre à jour. Prévoyez ce délai avant de prévoir une soumission.

Qu’est-ce qu’un accès « partiel » ?

Sur une Page ou un compte Instagram, vous pouvez parfois n’autoriser que les outils professionnels, et seulement les statistiques. C’est souvent suffisant pour lire des chiffres. Cochez uniquement les cases nécessaires, puis enregistrez.

5. Utiliser les MCP au quotidien

Une fois la connexion vérifiée, la valeur vient de la régularité. Voici une routine simple, sans automatisation risquée.

Ouvrir la période

Demandez un résumé des 7 derniers jours : publications, portée, interactions.

Repérer un changement

Comparez avec la semaine précédente. Cherchez une hausse, une baisse ou un sujet qui revient.

Lire les retours

Demandez les commentaires récents, puis demandez-en un résumé thématique.

Noter une décision

Écrivez une action possible, mais ne l’exécutez pas depuis le MCP sans accord explicite.

Exemples de demandes

« Liste mes pages accessibles. Ne modifie rien. »
« Donne la portée et les interactions des 7 derniers jours, avec la semaine précédente à côté. »
« Résume les commentaires reçus hier par thème. »
« Avant de publier quoi que ce soit, dis-moi exactement ce que tu vas faire et attends mon accord. »

Bonnes habitudes

  • Demandez une période précise : « 7 derniers jours » plutôt que « récemment ».
  • Demandez un format court : 5 lignes, un tableau, trois points.
  • Ajoutez « ne modifie rien » quand vous voulez seulement lire.
  • Gardez une trace des demandes importantes : cela aide à comprendre un chiffre qui change.
Le réflexe à prendre

Si une réponse vous semble étrange, demandez : « Quel outil as-tu utilisé, et quels chiffres as-tu lus ? ». Un bon MCP doit pouvoir expliquer son chemin.

6. Dépannage sans jargon

« needs authentication »

La connexion a expiré ou n’a jamais été faite. Reconnectez-vous via la procédure du client. Vérifiez la date d’expiration si vous utilisez un token de service.

« Permission manquante »

L’autorisation n’est pas dans l’application, ou elle n’est pas encore approuvée pour un accès avancé. Vérifiez la liste des autorisations avant de changer le code.

« 0 appel sur 1 »

Un appel de test a peut-être réussi, mais Meta n’a pas encore mis à jour le compteur. Patientez jusqu’à 24 h avant de conclure à un échec.

« Port déjà utilisé »

Un autre programme occupe le port local. Choisissez un port libre et gardez la même valeur dans toute la configuration. N’enregistrez pas cette adresse locale dans Meta.

« Aucun résultat »

Vérifiez d’abord le compte sélectionné et la période. Beaucoup de réponses vides viennent d’un filtre trop étroit, pas d’un serveur cassé.

« Serveur bêta »

Cela signifie que les noms d’outils peuvent bouger. Consultez la liste affichée par votre client plutôt que de recopier un ancien exemple.

Ordre de vérification

  1. Le bon serveur est-il ajouté au client ?
  2. Le client affiche-t-il les outils du serveur ?
  3. L’authentification est-elle à jour ?
  4. L’autorisation nécessaire est-elle bien cochée ?
  5. Une lecture simple fonctionne-t-elle ?

Suivez cet ordre. Il permet de corriger une cause à la fois, au lieu de tout réinstaller.

8. Checklists

Avant de connecter un MCP

  • J’ai identifié le besoin précis : lire des statistiques, des campagnes, des commentaires…
  • J’ai choisi un seul serveur pour commencer.
  • J’ai vérifié que mon client MCP le prend en charge.
  • J’ai prévu une application Meta dédiée, avec un nom compréhensible.
  • Je n’ai coché que les autorisations nécessaires.
  • J’ai prévu un test de lecture simple.

Avant une action sensible

  • Je sais exactement quel compte sera touché.
  • Je sais si l’action lit ou modifie.
  • J’ai demandé une confirmation explicite avant de publier, répondre ou modifier.
  • Je n’ai pas collé de token, de secret ou de mot de passe dans la conversation.
  • Je garde une trace de ce qui a été fait.

Avant de partager ce guide

  • Aucun identifiant réel n’a été ajouté dans le document.
  • Aucune capture contenant des données privées n’a été insérée.
  • Les exemples utilisent des espaces réservés comme <ID_DE_LA_PAGE>.
  • La version exportée en PDF a été relue après impression.
Si vous ne retenez qu’une chose

Connectez le strict nécessaire, testez une lecture, puis avancez par petites étapes. Un MCP bien configuré doit vous rendre le contrôle, pas vous le retirer.

Dernier mot

Un MCP n’est pas une baguette magique. C’est un outil avec un nom, des paramètres et des droits. Quand vous savez quel outil appeler, pourquoi l’appeler et quoi refuser, vous êtes en contrôle. C’est exactement ce que ce guide cherche à vous donner.
